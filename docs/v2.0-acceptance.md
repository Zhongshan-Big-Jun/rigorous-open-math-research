# 2.0 能力验收与证据范围

本页记录真实工具行为和一次原文复用检查. 发布状态, 最终运行时检查与同步记录见 [实施记录](v2.0-implementation-status.md). 本轮没有用已有 Q9 证明声称 2.0 发现了新数学, 也没有把入口缩短换算为模型提速.

## 文献读取与新会话复用

使用 Yan, Shi, Zhao 的 [arXiv:1711.07032v1](https://arxiv.org/pdf/1711.07032v1), 下载固定版本 PDF, 提取并读取第 1, 2, 22 页. 第 22 页通过实际图像核对. 原文内容, 来源版本, 原始 PDF 和选页文字的 SHA256, 定理与公式定位均保存在工具库中. 没有把下载整篇 PDF 写成审读整篇证明.

整理者建立一张关于分离边界条件的工具卡, 再添加关于参数符号和拟导数的批注. 无须重建索引, 新批注即能被检索. 随后使用一个不继承本次对话的 agent, 仅给出新问题, 工具库和读取工具入口. 它实际查询指针, 打开卡片和批注, 再按返回偏移读取原文.

| 检查内容 | 观察结果 |
| --- | --- |
| 找到实际工具和原文 | 一次关键词查询命中相关卡, 来源与批注哈希有效 |
| 连续读取 | 三次有界读取覆盖所提供的 154 行选页文字, 偏移连续, 末次返回无剩余 |
| 适用性 | 正确转换左右边界的参数符号, 区分正参数极限与另一侧奇异极限的谱编号 |
| 定义范围 | 没有把拟导数边界条件直接替换为缺少端点正则性的普通导数条件 |
| 原文与推导 | 分别列出论文陈述, 参数代换推导及尚未支持的范围 |
| 保护原始材料 | 工具库的 8 个输入文件与运行前哈希完全相同, 证据标签未升级 |

复用答案由协调器对照已读取原文和直接代数核对. 协调器同时是卡片整理者, 因而这不是独立盲审实验. 新会话记录的检索观察用时约 105 秒, 到答案整理约 254 秒; 只有一次观察, 没有速度对照和完整计费用量, 不据此推断提速.

检查发现一个实际可读性问题: 卡片写有 `scope`, 查询摘要却只显示未填写的 `conditions`. 已让索引和查询分别保留并显示两者, 旧索引刷新时补读该字段. 修复检查在副本上进行, 原始问题, 卡片, 批注, 索引和答案保持冻结. 一次选页文字断言还遇到双空格差异, 修正的是验收程序的匹配方式, 原文与读取工具没有被改写.

来源指纹, 原始答案与命令记录的哈希, 分页信息和实际限制见 [文献复用记录](v2.0-evidence/literature-reuse.json). 完整本地工件位于维护主机 `F:/tools/math-plugin-v2-20260909/literature-acceptance/`. 原论文及完整抽取文本没有复制进插件发行包.

## 旧工具与困难题证书复用

以主项目的 77 张旧卡, 三条既有索引记录和冻结 Q9 材料建立隔离副本. 原始 89 个输入文件哈希不变, 旧 ID 和自定义元数据保持对应. 九个冻结证据绑定与原证书的全部 230 个系数核对通过.

随后由新的确定性进程检索证书程序, 对记录范围内的新子矩形重新计算 130 个有理 Bernstein 系数, 得到严格正的最小值. 范围外请求明确返回 `NOT_COVERED`, 没有把方法不适用误报为原命题的反例. 这说明程序, 范围和证据指针能够经过整理后继续复用, 不等于新的 agent 解决了困难题.

[冻结回放记录](v2.0-evidence/frozen-q9-reuse.json) 保留数值, 证据摘要和完整本地结果的哈希. 可用发行源码中的 `test_library_q9_reuse.py --output OUTPUT --legacy-project PROJECT` 重放; 已安装插件不包含大型 benchmark 原件时, 该可选测试会明确跳过.

## 自动化行为检查

文献与经验的 26 项测试及七项旧兼容检查已在 Linux 和 Windows Python 中执行. 覆盖实际子进程中断后重试, 旧卡与批注身份, 部分坏元数据, 过期引用, 人写区域保留, 条件性再检视, 候选解释和索引重建. 最终命令与版本以实施记录为准.

续接模块经过独立缺陷复现后修正: 保存和外部结果均从同一次字节读取计算哈希, 保存前复核当前内容; 子进程已启动后的记录错误保留为 UNKNOWN; 启动前输入变化阻止派发, 运行边界发现的变化不会因后来还原文件而消失. 普通可变文件任务只报告观察到的匹配情况, 不承诺其输入在整个执行期间不可变. 进程中断与 Windows 文件占用等共 24 项测试在本机 Windows 全部通过; Linux 通过其中 22 项, 两项专门的 Windows 检查明确跳过. 保存接口对不遵守同一锁的编辑器不提供无条件 compare-and-swap 保证.

Lean 4.31.0 的 11 项真实检查通过, 产生 23 份验证清单: 11 个按预期闭合, 12 个按预期不闭合. 覆盖错误/加强后的目标, 隐式实例和宇宙参数, 隐藏在定义及类型中的公理, 条件路线, 篡改/过期收据, 证明体修改后的语义复核复用, 以及实际 LSP 与 CLI 反馈. 另有 12 项便携测试在 Linux 与 Windows 通过. 这些测试使用小型真实 Lean 工程; 没有宣称完成整个 Mathlib 或成果仓库的形式化.

独立审查报告与最终发布前复核状态将在实施记录中明确列出. 旧兼容检查共 18 个脚本通过, 四包的结构与元数据校验通过, 仓库校验共 81 项通过.

后续续接复核发现, 损坏 observations 容器会阻断整体检查, 状态保存重试会推迟超时执行. 已增加逐记录验证及独立于保存重试的子进程计时, 扩展后的 26 项测试在 Windows 全部通过, Linux 通过 24 项并跳过两项 Windows 专用检查. 独立审查者在两平台复现原问题并运行成功对照, 确认全部已报告续接缺陷关闭. 范围与源码哈希见 [续接复核记录](v2.0-evidence/recovery-review.json).

后续独立 Lean 审查复现了初始用例未覆盖的三个缺陷: 只在预期类型中出现的外部定义变化, 带引号的本地 import 绕过依赖重编译, 以及更高优先级的新模块遮蔽原依赖. 修复后原三个复现通过独立验收, 完整 14 项检查也通过, 随后审查者又发现普通记号提供者可能消失于最终类型依赖, 仍会导致错误复用旧结果.

最终改为绑定全部实际载入模块, 核对完整数量, 同时保留较小的类型/定义依赖集供语义复核复用. 新增的原生 Windows 对照覆盖记号只出现在预期类型或源类型中的两种情况, 四次验证及旧收据失效/恢复检查通过. 独立原生复核也通过九项断言, 涉及另外四次验证和四次依赖编译, 13 个源码文件哈希不变. 具体范围见 [Lean 复核记录](v2.0-evidence/lean-review.json). 当前完整套件有 15 项真实测试; 精确提交的云端执行状态见实施记录链接的 Actions.

本地收据及 SHA256 提供对应材料的一致性和失效检测, 不是防止整套证据被一起伪造的签名信任根. 语义复核复用表示已有复核记录的绑定仍然匹配; 工具不会自行认证审查人的身份, 独立性或数学判断. 未绑定的非形式化来源变化也无法由哈希检测.

测试程序的 PASS 只说明对应检查通过. 形式化定理是否闭合仍由实际 Lean 目标与依赖决定, 数学结论是否值得接受仍取决于其证据和审查. 拟定的 1.x / 2.0 / 空白三臂困难题研究实验尚未执行, 不与本页工程验收混计.
