# 2.0 implementation and evidence

All four packages implement `2.0.0`. The accepted [design](v2.0-refactor-plan.md)
is preserved. This page records the versioned source and observed local checks.
[GitHub Actions](https://github.com/xsoc1/rigorous-open-math-research/actions)
reports remote execution for each commit; `codex plugin list --json` reports a
particular installation. Source files alone cannot establish which version an
existing conversation has loaded.

## Delivered source

| Area | Implementation |
| --- | --- |
| Workflow guidance | Four concise, independent entries. No fixed phase sequence, role roster, routine quota gate or compulsory Lean stage |
| Literature and tools | Captured source versions, bounded reading, editable cards, immediate annotations and reconstructible pointers; damaged records are isolated |
| Research experience | Useful mechanisms from success and failure, reconsideration conditions, route comparison with supplied testable candidate explanations, human-editable understanding |
| Continuity | Atomic progress and history, input-bound checkpoints, detached jobs, stable request IDs, real process identities and explicit unknown external outcomes |
| Lean | Compiler and interactive feedback, exact actual/expected types, transitive definitions and axioms, complete loaded-module freshness, reusable supplied semantic-review bindings and conditional routes |
| Compatibility | Historical pipeline checking explicitly uses `--legacy-v1`. Existing source cards, annotations, sealed checkpoints, canonical receivers and frozen benchmarks retain their identities |
| Documentation and cleanup | Bilingual READMEs and focused guides; long maintenance history archived; one unused phase-splitting program removed |

The four skill entries total 12,496 bytes, compared with 101,524 before this
refactor. This is a byte measurement, not a measured model-cost or research-speed
improvement. Tools preserve evidence; they do not automatically discover or
accept mathematical conclusions.

## Observed checks

- Repository: 81 structural checks passed after the final context amendment.
  All four plugin and four skill validations passed. The 18 compatibility smoke
  scripts passed after the earlier dependency-resolution amendment; CI runs
  their current versions for each candidate.
- Library and experience: 26 behavior tests and seven legacy library checks
  passed on Linux and native Windows, including damaged-record isolation,
  Unicode continuation, versioned annotations and human-region preservation.
- Recovery: 26 tests passed on Windows; 24 passed and two native-Windows cases
  were skipped on Linux. Independent review reproduced and closed all reported
  persistence, process, input-boundary, timeout and corruption-isolation defects.
  [Evidence](v2.0-evidence/recovery-review.json).
- Lean: the initial 11 real controls and 12 portable controls passed. After the
  first dependency fixes, all 14 real controls passed in 661.867 seconds through
  Windows Lean 4.31.0 and WSL Python. Independent review then found the erased
  notation-provider gap, so those 14 results are historical rather than final
  coverage of the complete-context amendment.
- The final Lean amendment passed 12 portable checks. Its new native Windows
  test covered both expected-type and source-type notation, with four verifier
  manifests, stale-receipt checks and restored positive controls in 149.593
  seconds. Independent native rechecks passed nine assertions across four
  additional manifests and four dependency compilations. All 13 frozen source
  hashes remained unchanged. [Evidence](v2.0-evidence/lean-review.json).
- The current real Lean suite contains 15 tests and is explicitly enabled in
  CI with Lean 4.31.0. The minimal Lake fixture was generated with actual Lake
  and checked against the official action configuration. A workflow definition
  is not a completed run; use its exact-commit result and retained compiler logs.

The first candidate's [actual CI run](https://github.com/xsoc1/rigorous-open-math-research/actions/runs/34333791063)
passed repository, legacy smoke and Linux maintenance checks, but exposed two
portability gaps. Windows short directory aliases were compared with resolved
roots, and generated Lean inspection files were compiled outside the project's
pinned toolchain context. The fixes normalize recovery roots and retain the
project working directory for inspection. Recovery tests also wait for a
terminal supervisor to close its logs before deleting temporary files. The
amended recovery suite passed all 27 cases on native Windows and 25 cases with
two platform skips on Linux. Earlier frozen review identities remain historical;
the exact-commit CI result establishes the current complete suite outcome.

Native Windows Python was used for the final full-context checks. This avoids
cross-system file access when the compiler and files are on Windows volumes.
The runs above differ in scope and are not a controlled platform-speed study.

## Actual reuse acceptance

One fresh-context agent found and applied a theorem from a captured fixed-version
paper using a card, an annotation and original-text pointers. The original eight
input files stayed byte-identical. A query-summary scope omission discovered
during the exercise was corrected on a copy. The answer was checked against the
selected original pages by the coordinator, who also authored the card; this
was not a blind independent study. [Acceptance](v2.0-acceptance.md).

The final real-data migration replay preserved 89 input hashes, 77 old cards and
three legacy index rows. It verified nine frozen evidence bindings and all 230
certificate coefficients, then recomputed 130 coefficients on a new subrectangle
in a fresh deterministic process. Out-of-domain reuse returned `NOT_COVERED`.
This was a known-proof engineering replay, not a new proof of Q9.

changed and 125 listed files were removed. All 61 document PDFs parsed; canonical
gateway structural validation passed without changing mathematics. The exact

archives, whose staged blobs were compared in full. Forty-four unrelated dirty
paths remain unchanged and unstaged. The cleanup report records inherited
historical hash limitations; this release does not conceal them or upgrade
canonical mathematical claims.

## Installation, synchronization and limits

Use the [installation and migration guide](v2.0-guide.md). Refresh the
`math-research` marketplace, install the four selected packages, compare actual
cache identities with the published source and start a new conversation.
Other marketplaces and standalone skill copies have separate identities.
The [DSH adapter](https://github.com/xsoc1/math-research-dsh) records its exact
parent in `upstream.lock.json` and synchronizes from its canonical parent clone.

Local evidence and the original dirty-work backup are under
`F:/tools/math-plugin-v2-20260909/`; the original library migration evidence is
under `F:/tools/math-research-v2-library-20260909-final/`. Installation and remote
delivery receipts are kept separately from frozen research evidence.

The proposed 18-solve, three-arm research comparison has not run. It remains a
follow-up performance study. Existing 1.x comparisons and engineering replays
cannot establish 2.0 research gains. Fuse/Prove2Me cloud services and a second
independent kernel checker are not integrated. Supplied semantic-review records
are not authenticated mathematical judgments. No quota polling or reserve gate
is used by the default workflow.
