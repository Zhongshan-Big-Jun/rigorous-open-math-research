# 2.0 重构方案: 数学研究工作流程引导

日期: 2026-09-09. 修订: 2, 已纳入 Fuse / Prove2Me 调研方法. 状态: PLAN_ONLY. 目标发布版本: 2.0.0, 对外简称 2.0.

本方案的原始现状基线为提交 `2582d7ee628f005f3e9a1178d51ba8a07721241d`. 本次按用户要求, 将 [Lean 平台调研](lean-verification-platform-research-2026-09-09.md) 的方法纳入同一方案, 更新验证工具, 审计分工, 工具库指针, 恢复及验收设计. 调研与诊断证据固定于提交 `7289a01f197faaa9e0b19c3b64dc53fbb20b78c4`; 修订前方案仍可从该提交追溯. 当前只修改方案和维护文档, 插件实现与已安装版本仍为 1.x, 各实施批次尚未开始.

## 1. 目标与依据

2.0 的定位是给有能力的研究 agent 提供项目记忆, 可调用工具和简短工作引导. 研究路径, 搜索时机, 并行方式, 检验方法和成果组织由 agent 根据问题决定. 插件的价值重点转向跨论文和跨会话的知识积累, 而不是规定 agent 如何思考.

当前证据足以支持大幅撤掉默认流程负担:

| 已完成比较 | 观察 | 对 2.0 的含义 |
| --- | --- | --- |
| L1 两题, 旧版 A / 新版 B / 空白 C | 六份答案全部通过外部盲审, 空白组两题完整交付成本均最低 | 不再以更严密的流程推定更高求解效率 |
| 主项目困难 Q9, 同一账号 Astra/max, 有效阶段均未中断 | 三组均 PASS 100/100. B 比 A 完整交付耗时多 4.75%, 输出多 28.48%, 非缓存输入少 1.32%. C 最快 | 优先删除强制调度与重复整理, 保留空白对照 |
| Q9 的自主行为 | 空白 C 自行使用三个子任务并提供精确证书 | 子任务, 检验和证书可以由模型判断何时采用 |
| 文献和恢复功能 | 已有真实文件回放及确定性检查, 尚无完整的文献复用和受控中断验收 | 2.0 要直接证明这两项核心能力的实用价值 |

证据来源: [L1 结论](../benchmarks/codex-20260906-l1/CONCLUSIONS.md), [Q9 结论](../benchmarks/codex-20260908-q9/CONCLUSIONS.md), [Q9 机器数据](../benchmarks/codex-20260908-q9/comparison.json), [第一批实现记录](optimization-20260905-progress.md).

这些是少量题目的观察, 不能证明 Astra 的普遍能力发生了多少变化, 也不能归因某一条规则造成多少额外成本. 共同外审属于实验评分装置, 不构成插件必须强制内部外审的证据. 2.0 据此改变设计方向, 不预先宣称提速幅度.

本次修订采用调研中有具体代码或文档依据的方法:

| 调研所得 | 纳入 2.0 的设计 | 验收位置 |
| --- | --- | --- |
| Fuse / Numina 的编译反馈, 声明检索和局部证明拆分 | 按需复用 Lean 交互环境, agent 自主决定路线与分工 | 第 5.2 节, Lean 工程试点 |
| Prove2Me 的稳定声明, 独立证明对象与条件归约 | 从实际 Lean 对象生成依赖, 计算选定路线是否闭合 | 第 5.3 节, 根依赖验收 |
| 盲回译及挂谷的跨定义连接 | 审计根命题, 关键定义和转换的含义; 未变部分复用证据 | 第 5.4 节, 陈述保真验收 |
| 平台任务身份与持久结果 | 将编译/验证任务接入现有恢复入口, 显式处理未知结果 | 第 4.2 节, 在途任务中断验收 |
| 本地验证器缺失/超时误报通过, Lean 注释误报 | 优先修复结果判定, 补充精确目标及传递公理检查 | P0, 第 5.1 节 |

来源和证据等级以 [调研报告](lean-verification-platform-research-2026-09-09.md) 及 [隔离诊断](research-20260909/verifier-probes.json) 为准. 这些支持方法选择, 不是平台效率的受控比较或本机重放大型证明的结果. 本方案吸收其工具方法, 不照搬固定尝试次数, 人工 captain 审批链或强制多 agent 角色.

## 2. 产品结构与版本范围

保留现有四个插件 ID 和 skill 名称, 四个发布包在完成重构后统一升为 `2.0.0`. 这样保留用户调用习惯和 DSH 对接入口, 同时明确整套默认行为发生大版本变化. 不在本次计划提交中提前改版本号.

| 入口 | 2.0 职责 | 加载方式 |
| --- | --- | --- |
| `math-research-workflow` | 简短的研究工作引导, 指向项目状态和需要的能力 | 完整项目工作或续接时使用, 不自动串起三个完整技能 |
| `rigorous-open-math-research` | 单个数学问题的研究入口, 帮助定位问题和可用项目材料 | 单题可直接进入研究, 无强制管理阶段 |
| `manage-math-research-program` | 文献内容, 工具卡, 批注, 指针表和项目状态的使用说明 | 需要知识维护或恢复操作时按需读取 |
| `lean-verify` | Lean 交互构造, 精确目标验证及针对性的语义核对 | 用户要求或研究中需要时使用, 可以先检验局部猜想或引理 |

这些职责是便于发现功能的目录, 不再是限制同一个 agent 工作内容的角色边界. 管理文献时可以直接推导一个引理, 求解时可以直接查库和批注, 不必为了换角色再开 agent. 各入口保持可独立使用, 共享操作只保留一份权威说明, 不把另外三个技能全文再次嵌入.

基础能力继续使用本地文件库与 Lean CLI, 保留四个现有安装包. Lean 交互进程可以按需启动和复用, 不作为必须预先部署的常驻服务. 云平台, 新数据库和另一套编排框架均不属于基础依赖. 在可观察到重复加载时修复实际加载路径.

### 入口体积目标

本次实际测量的 UTF-8 文件字节数如下. 它们不是 token 数, 也不表示每次请求都会加载全部四个入口.

| 入口 | 当前版本 | 当前字节数 | 2.0 设计目标 |
| --- | --- | ---: | ---: |
| workflow | 1.15.0 | 29,175 | 约 2,500 |
| rigorous | 1.12.0 | 13,794 | 约 3,500 |
| manage | 1.8.1 | 39,337 | 约 5,000 |
| lean | 1.6.0 | 19,218 | 约 5,000 |
| 合计 | | 101,524 | 约 16,000 |

合计目标约缩减 84%. 这是文档设计目标, 不是限制研究输出或思考长度的规则. 不为了达标压缩数学内容, 不把被删的强制要求搬进默认必读参考文件. 实验另外记录实际加载的入口和参考文本, 包括子任务继承内容, 避免用静态文件缩短冒充运行成本下降.

本次新增的 Lean 设计属于工具实现和维护验收说明. 普通入口只说明能力, 调用时机和结果含义; 具体接口, 故障处理及平台资料按需读取, 入口体积目标保持不变.

| 多份白板, ledger, map, route registry, closure gate, reuse summary | 合并重复语义 | 普通持续研究只维护一份当前进展记录, 证明和实验按实际内容保存 |
| 每个承重 worker 结果都要另派审计, 完成后再 fresh audit | 改为自主选择检查范围和时机 | 可以集中检查最终论证, 也可以提前检查脆弱引理; 报告实际做过的检查 |

| Lean 完成状态统一要求独立审计重新核对每个证明义务 | 改为机器推导检查与针对性语义核对 | 重要目标和定义可做盲回译, 已确认且未变的语义审查可复用 |
| Lean 检查必须无状态, 固定 5 次 / 10 分钟构建限制 | 改为按输入与进程状态管理工具 | 复用交互环境和有效缓存; 并发冲突与重复挂死由工具诊断 |
| fast-close 后只能有一次带 manifest 的 frontier call | 删除特殊研究调用许可机制 | 按用户目标判断何时完成或继续, 不新增插件自己的批准流程 |
| 每阶段 git 同步, 环境 doctor 和全项目 gate | 取消插件层的逐阶段强制调用 | 遵守用户及项目自己的维护约定; 环境变化或故障时做相关诊断 |
| 固定输出标签, 全套结果模板和性能告警报告 | 取消普通回答的格式要求 | 清楚交付结论, 依据与未解决部分; 结构化字段仅供实际工具接口使用 |
| 额度轮询, 人为保留线, token 分层和因额度快照过期暂停 | 从默认研究流程移除 | 仅在用户明确设置预算时采用; 服务实际中断后走恢复入口 |
| 恢复前必须持有完整旧收据, 只准执行旧 `first_action`, 最多读 12 个文件 | 删除对研究行为的这些硬限制 | 检查现有工件和正在运行的工作, 按当前用户指令决定下一步; 必要时可查历史 |

最后一行不允许把变更过的文件继续报告成原来的已核验版本. 证据失配只影响相应证据的可信状态和写入操作, 不应阻止 agent 调查问题或继续其他研究.

只把与结果含义和数据操作直接相关的条件留在对应位置:

- 证明, 猜想, 数值证据和实际验证状态如实区分. 来源和运行结果来自真实内容, 原问题的假设或目标变动明确说明. 入口用简短表述承载, 不在每个 phase 重复.
- 文件版本, 原文位置, 批注所属卡片版本和并发写入由工具处理. 校验失败只阻止不可信数据的误用或有冲突的写入.
- 项目已采用的 accepted knowledge 接收协议继续用于真正的规范知识库写入. 普通草稿, 方法笔记和候选工具卡可以先保存并检索, 不为记下一条想法走一遍接收流水线.
- Lean 工具核对所声称的完整目标, 实际依赖和执行状态. 编译成功, 条件归约, 根证明闭合与含义已核对分别呈现; 未执行或未完成不报告通过. 具体语义见第 5 节.

现有用户授权和项目规则继续适用. 插件不借用上述条件增加新的用户确认环节.

## 4. 两项核心能力

### 4.1 实际阅读文献, 形成可批注工具库和指针表

保留 [research_library.py](../plugins/manage-math-research-program/skills/manage-math-research-program/scripts/research_library.py) 已实现的内容捕获, 分段读取, 卡片索引, 批注和版本关联. 当前 helper 本身不负责网络搜索和网页阅读, 2.0 仍使用当时可用的网络工具读取来源, 再将实际内容交给本地库. 不假设某个外部文献插件必然可用.

正常使用可以是: 搜到论文, 读相关正文或 PDF 页, 留下有用工具卡, 在下一道题中通过指针取回并检查适用条件. 研究无需先完成整篇论文分析才能使用其中一个明确结果.

重构内容:

1. 将文献读取说明浓缩成按需入口. 保留来源版本与原始页码/定理/公式位置. PDF 提取行号只帮助检索; 关键公式提取有疑问时回看原页. 只读到摘要或片段就记录实际可得范围.
2. 工具卡以稳定 ID, 数学内容或操作, 已知适用条件, 来源/推导指针和自由笔记为中心. ID 和机械元数据可自动补齐. 例子, 别名, 关系, 成熟度扩展等按有用程度补充, 取消当前十多项字段齐备才能形成完整卡片的写作负担.
3. agent 能直接追加用途, 改写方式, 易错条件, 失败实例或更正线索. 普通注释即时可检索, 不因尚未审计而不能入库. 有来源的定理和待核实的想法都可以保存, 检索结果显示各自的证据状态.
4. 延用 `index/tools.json` 和工具库 README 的指针作用. 索引由工具生成, 人工或 agent 不重复抄写目录. 查询返回少量相关指针及概要, 需要时再读取卡片和批注.
5. 简化旧卡兼容和索引刷新. 保留原卡和自定义目录, 增量更新变更项. 缺字段或坏卡只影响对应记录, 健康记录仍可查询. 若一条记录的完整性无法确认, 返回可调查的状态和路径, 不伪造正常命中.
6. 卡片改版后保留原批注及其版本联系. 过期批注作为带说明的历史可查看, 不静默当作当前适用条件. 同一写入重试不重复造卡或造批注; 卡片归并由实际数学内容决定, 不用标题相似自动合并.
7. 有形式化成果时, 工具卡可引用固定版本的 Lean 声明, 验证结果和数学转换引理. 相关索引由工具生成, 普通文献卡仍可独立存在. 具体关联见第 5.5 节.

现有 [library-runtime.md](../plugins/manage-math-research-program/skills/manage-math-research-program/references/library-runtime.md) 和 [tool-library-spec.md](../plugins/manage-math-research-program/skills/manage-math-research-program/references/tool-library-spec.md) 将合并整理使用说明, 保留必要的来源和版本语义, 删除字段排场和跨 skill 转交要求. 先改善现有文件库, 不预先引入向量数据库.

### 4.2 中断后从实际进度续接

普通研究的恢复语义源是一份当前进展记录, 优先复用项目已有的 `RESUME.md` 或白板. 其中只需容纳当前目标, 已有结论及文件指针, 尚未解决的问题和下一步建议. 当前实验/子任务确实存在时才记录其身份, 输入和状态. 这些是有用信息, 不限定 Markdown 标题和固定表格.

工具负责机械信息, agent 负责少量研究语义:

1. 合并现有 inspect, receipt, advance 的常见操作, 提供一次调用可用的保存/恢复入口. 路径, hash, 操作 ID, 写入冲突和旧状态转换由代码处理, 不让 agent 手工凑多份 JSON.
2. 在产生可复用结果, 路线决定或交接时及时保存. 已通过工具提交的批注和结果自动落盘. 2.0 不假设能拦截任意 Codex 内部动作, 也不承诺恢复从未写出的推理或无返回调用.
3. 恢复时先给出简短当前状态, 相关工件和未完成工作. 原会话可用则沿原会话继续; 不可用则由当前接手者使用这些持久工件. 不因恢复需要而自行创建用户侧新任务.
4. 把 checkpoint 中的下一步视作建议. 新消息, 后续已返回工件或已失效前提都可以改变它. 已完成或已明确失败的动作避免无理由重放, 但发现新的条件或需要独立复核时可以重新研究并说明原因.
5. 核对实际仍在运行的子任务和编译/验证任务, 仅对状态不明的动作先调查, 不重复提交同一外部写入. 无关的研究工作可以继续, 不以一个待核对任务锁住整个项目.
6. 没有旧 checkpoint, 只有部分文件或最新草稿未封存时, 允许从实际工件重建进度并标注不确定部分. 有 hash 冲突时保留旧证据, 调查变动, 更新受影响状态. 不用旧快照覆盖较新的成果.
7. 编译或验证启动前保存操作身份和输入快照, 取得本地执行身份或远程 job ID 后立即落盘, 结果绑定完整日志与终态. 恢复时先核对原任务: 已完成则收取结果, 仍运行则继续跟踪, 已失效则从同一输入重建执行. 迟到的旧结果只归属于旧快照, 不覆盖新版本的验证状态.

对远程响应丢失, 只有服务支持幂等键或可查询身份时才自动去重续接. 无法核实调用是否生效时保留未知状态并调查, 不承诺 exactly-once. 本地进程身份也要防止把复用的 PID 当成原任务. LSP / REPL 和缓存是可重建的加速层, 恢复依据是源码, 环境和已保存结果.

沿用 [checkpoint_resume.py](../plugins/math-research-workflow/scripts/checkpoint_resume.py) 和 [recovery_status.py](../plugins/math-research-workflow/scripts/recovery_status.py) 可复用的读写与幂等逻辑. 把旧的完整研究阶段门禁拆出去. 现有封存检查点保持可验证, 转入 2.0 时创建带旧来源指针的新状态, 不改旧文件.

计分实验所需的处理组, 剩余时限, 累计用量和封存绑定继续归 benchmark harness 管理, 不再扩散成每次日常研究都必须执行的恢复协议. 不增加额度轮询或定时自动恢复任务.

## 5. Lean 形式化, 验证与语义审计

这一能力可在研究过程中随时使用. 小目标直接写 Lean 文件, 大目标需要时再拆分和并行. 工具对证据作明确判定, agent 自主决定采用哪些研究方法.

### 5.1 精确目标与真实执行结果

优先修复 [verify_lean_project.py](../plugins/lean-verify/scripts/verify_lean_project.py) 的缺失/超时汇总和注释扫描问题. 所有指定目标均实际完成并通过时, 相应构建状态才能为成功. 缺失, 超时, 工具不可用和未知结果分别给出原因. stdout / stderr 完整落盘, 面向 agent 返回相关诊断与日志指针. 源码扫描正确处理 Lean 嵌套块注释等语法, 用于定位未完成项, 最终证据来自实际 Lean 环境.

验证输入绑定目标的完整声明名, 预期类型, 关键定义与依赖环境. 类型检查覆盖显式和隐式参数, universe 和 typeclass 前提; 定义闭包参与版本身份, 避免同名定义改变含义而仍复用旧结论. 数学上等价但并非定义相等的接口, 用显式转换证明连接到预期目标. 冻结的是被验证的目标版本, 探索中的其他定义和引理可以继续改进.

从实际 elaborated 声明读取传递公理和依赖, 包含类型与定义内部的依赖. 通常公理策略允许 `propext`, `Classical.choice`, `Quot.sound` 的子集, 不要求每个定理使用全部三项. 额外公理及 native evaluation 的信任依赖按实际 Lean 版本呈现. `H -> T` 即使没有额外公理也不能替代目标 `T`; 原委托目标本来包含的数学假设则照常保留.

以下信息是同一结果对象的组成部分, 由工具生成或引用已有记录, 不增加四份手写报告:

| 结果内容 | 解释 |
| --- | --- |
| 目标和含义 | 实际声明, 预期类型, 相关定义, 对应数学来源及语义核对状态 |
| 机器执行 | 环境, 命令, 指定目标, 成功/失败/未完成原因及实际公理闭包 |
| 根依赖 | 局部归约与根证明是否闭合, 当前选定路线, 未完成叶子 |
| 证据身份 | 源码与依赖快照, 工具和配置版本, 完整日志, 结果及复用来源 |

最终声称完整形式化时, 在该快照上检查实际根目标. 仅编译某个文件, 默认构建目标或没有 `sorry` 字符串都不单独构成完成判据. 旧状态标签通过兼容层读取; 2.0 的声明级状态由这些证据推导, 不再以额外逐义务 LLM 审计作为统一条件. 语义尚未核对时可以报告该 Lean 声明已通过机器检查, 明示与原数学目标的对应仍待确认.

### 5.2 可复用的 Lean 交互反馈

提供 goal, diagnostics, hover, 声明定位与检索, 局部试验等可调用能力. 优先适配可用的 Lean language server / REPL, 用固定环境复用会话和编译缓存; 无交互适配时保留 Lean CLI 路径. Sorrifier 等局部拆分方法按需要使用, 不新增固定路线数或尝试次数.

修改后检查受影响目标, 稳定候选再做相应的根检查. 缓存键覆盖工具链, 依赖锁与有关输入; 环境或输入变化后失效相关结果. warm 进程可退出重建, 不能把旧诊断用作新版本的成功证据. 使用定向 imports 与结构化错误反馈改善实际等待时间, 以试点数据衡量收益.

[lake_build_guard.py](../plugins/lean-verify/scripts/lake_build_guard.py) 保留并发构建冲突保护, 将固定次数限制改成可诊断的进程与输入状态管理. 有实际改动的正常迭代可以继续, 对同一输入的重复挂死定位原因. 大型根重放与日常交互反馈使用不同执行范围.

### 5.3 稳定声明与条件证明依赖

大目标按需将声明和证明对象分开. 已登记声明有稳定身份, 多个候选证明引用该版本; 更改声明产生新版本, 旧证明与审计仍指向原对象. 草稿可使用 typed stubs 表达待解决引理, 工具清楚标记条件归约.

依赖从 Lean 对象自动提取, 区分类型依赖与证明体依赖, 与已有 Blueprint / 工具索引适配. 一个证明需要其所有依赖完成, 一个目标可以选用任意一条完整证明路线. 循环或未证叶子不能构成闭合路线, 未选用的失败或开放路线不阻止有效路线完成. 无需为单个小引理先建立整套节点台账.

最终将选定路线接入实际证明体, 重新检查根声明和传递公理, 包括定义中引用的证明. 图中的完成标记和局部 sketch 编译均不替代这一步. 公共结果只覆盖实际完成的声明, 不从中间定理的名称推定更强的一般结论.

### 5.4 针对数学含义的审计与复用

重要根命题, 新的核心定义, 跨论文转换或作为独立工具复用的结论, 优先核对其数学含义. 可采用盲回译: 独立上下文只看 Lean 声明与相关定义, 展开量词, 隐式前提, 非标准概念和退化情形; 再由研究者或审阅者对照原命题. 采用该方法时如实记录独立性, 不把看过原意的回述当成盲回译. 它不附带新的用户批准环节.

语义核对绑定类型, 关键定义及环境. 只有证明体改变且这些内容不变时, 复用已有语义核对并重跑受影响的机器检查. 声明, 定义或环境变化时, 由依赖关系指出需要复查的范围; 数学等价的变更可用转换证明支持. 只有局部变化时不自动重审整条研究历史.

Lean 已检查的推导不要求 LLM 逐步重新证明. 非形式论证中仍未形式化的部分, 外部数学引用与需要人理解的解释, 按其实际问题选择复核. 是否增设独立审计由任务需要决定, 不设置固定审计轮数或强制人类 captain 流程.

### 5.5 文献工具卡与形式化结果贯通

沿用第 4.1 节的工具卡和指针表. 存在 Lean 成果时增加可查询关联: 仓库与固定提交, 模块和完整声明名, 环境, 实际类型, 关键定义, 验证结果或未证叶子, 以及跨定义转换引理. 这些机械信息由工具提取, 索引可以重建, 与 Blueprint 中已有节点通过引用连接.

agent 继续自由补充使用说明, 适用限制, 失败实例和搜索词. 批注可立即检索, 形式化状态仍来自对应版本的证据; 批注不能扩大已验证的范围. 没有 Lean 的文献工具仍按其实际来源和成熟度使用, 不因缺少形式化字段而失去可用性.

### 5.6 平台适配与独立 checker 的范围

2.0 基础交付覆盖本地 Lean 工具, 声明/依赖检查, 语义核对接口和恢复. Fuse / Prove2Me 云接入与独立 checker 作为可选适配, 根据当时实际可用接口, 版本和任务需要决定. 本次调研未验证完整平台后端, 因而不把某项未核实的服务能力写成发布前提.

重要成果可增加 comparator 或 Nanoda 重放. 结果区分目标比较, 同一 Lean kernel 重放与另一套 kernel 实现检查, 记录工具及补丁身份和实际操作者. 不将研究工件中的无沙箱包装表述成隔离验证任意输入的服务. 第二 checker 不进入每次改写证明的默认循环.

## 8. 验收与对照设计

研究运行本身采用自由流程. 以下实验控制只用于回答 2.0 是否有效, 由测试装置处理, 不写入 SKILL 作为 agent 日常限制.

### 困难数学题的三组比较

- 保留已完成 L1/Q9 原结论. 它们可以检查工具回归, 不再作为 2.0 的新发现或泛化证据.
- 在实现候选版冻结后选择至少三个未用于调参的困难题, 优先取主项目尚未闭合且确有前期阻碍的不同问题. 预先写明难度证据, 完成目标及严格部分进展如何计分. 已知答案和本轮重构人员见过的证明不进入求解环境.
- 三组为冻结的当前 1.x, 候选 2.0 和无研究插件的 Codex. 同一题具有相同输入和基础工具权限, 各组的插件能力按分组提供. 固定实际模型/推理强度, 记录账号和环境, 使用新会话, 平衡处理顺序.
- 首批设计为每题每组两次独立尝试, 即 18 次求解及对应统一外审. 这是拟定的实验规模, 本次不启动. 次数在首次有效求解前冻结, 不按中途表现追加到有利结果出现为止.
- 外部审计者使用相同任务合同和判分要求, 看匿名答案及其必要证据, 不接收插件组别或成本. 组内是否自行找人复核完全由该组决定. 同模型外审的限制照实记录.
- 同时报告求解和完整交付的时间, 非缓存输入, 缓存输入, 输出, 子任务和实际返回响应. 实验时限对三组一致; 故障和无返回用量单列. 不把所有 token 当同价总和, 不将一次跑完视为统计上证明无退化.

### 文献到工具复用

使用真实可访问的一手论文与实际研究问题. 一次任务读取相关内容并形成工具卡和批注; 之后的新会话只拿到新问题与项目检索入口, 从指针找到该工具并据此完成可检查的推导或指出不适用原因. 空白组得到同样的原始项目材料, 自行选择如何组织.

验证实际原文与定位, 卡片适用条件, agent 注释的搜索可见性, 相关指针能否命中, 后续使用是否正确, 以及首次组织和后续复用的各自耗时. 覆盖卡片改版, 过期批注, 历史失败范围和单卡坏元数据. 单纯 PDF 下载成功或可搜索到一个标题不算完成这项验收.

其中至少一项复用任务带有实际 Lean 声明, 检查版本和前提是否匹配, 能否复用已有转换引理和验证结果. 普通批注可检索, 但不能更改被引用证明的覆盖范围.

### Lean 工具与审计验收

先用可执行的局部案例确认工具结果, 再开展形式化工程比较. 回归程序检查真实行为, 不以文档里出现某个关键词作为通过依据.

| 情形 | 通过标准 |
| --- | --- |
| 缺失目标, 超时, 工具不可用, 明确失败和成功 | 执行状态准确, 未完成不为成功, 保留诊断与完整日志 |
| 嵌套 Lean 注释/字符串中含 sorry, 实际未证依赖来自 imports 或 def | 注释不误报, 实际传递公理揭示未证依赖; 扫描和根检查各自覆盖范围明确 |
| 额外假设, universe 特化, 同名定义改变, 目标范围缩小 | 类型/定义身份检查或语义核对发现变化; 合法等价转换可明确连接到原目标 |
| 条件归约, 两个开放叶子, 循环与备选路线 | 局部成功不冒充根闭合, 循环不能自证, 一条有效路线可完成根目标 |
| 只改证明体, 改关键定义, 更换环境 | 不变语义核对可复用, 受影响结果正确失效, warm 缓存不冒充新检查 |
| 回译可见隐式前提, 空集/零值和不可满足假设 | 揭示实际 Lean 含义, 与原目标比较, 不只复述期望结论 |

工程试点从已有 Q9 工件选取输入明确的有理系数证书引理, 再选一个主项目定义连接引理, 用于检验工具和形式化接口. 这些已知结果不作为新数学发现证据. 试点与第 8 节困难数学题对照分开记录, 不擅自扩展成重跑完整 Kakeya / FLT.

形式化比较也保留 1.x / 2.0 / 空白三组, 固定数学输入, 实际模型和 Lean / Mathlib 环境, 冻结各组可用工具与缓存条件. 报告正确闭合目标比例, 假通过, 语义漏检, 总交付时间, 编译等待与重复编译, 模型用量和审计复用. 若需要区分提示词与新工具的贡献, 再做工具相同的局部消融, 不将平台名或进程复用直接等同于已测得提速.

### 受控中断与恢复

在有真实进展的研究中预先选定可观察的中断点, 覆盖已保存结果, 批注/索引写入边界, 子任务及编译/验证在途状态. 同时测试原会话续接与仅凭落盘材料接手, 采用故障注入, 不实际耗尽账号额度.

与相同任务的不间断路径比较: 已保存成果是否保留, 有无重复副作用, 失败机制是否丢失, 最新工件是否被旧快照覆盖, agent 能否调整已经不合适的下一步. 记录恢复额外读取和耗时. 对未落盘内容保留未知状态, 不编造恢复成功.

额外覆盖任务入队后响应丢失, 结果返回前源码已更新, 原进程失效与缓存重建. 已确认任务沿原身份取回结果, 结果未知时不会盲目重复外部写入, 旧快照结果不会使新目标自动变为已验证. 未接入真实云服务时明确区分本地实测与协议模拟, 不宣称生产平台端到端恢复已通过.

### 发布判断

发布以真实能力验收和兼容性为依据. 文献引用失真, 恢复覆盖较新成果, 旧失败限制被静默抹掉, 未完成误报成功或错误目标被当成完整证明都属于需要修复的实质问题. 对研究效率逐题报告分布和差异, 不以多生成文档计为收益. 云平台和独立 checker 未接入时按实际范围发布本地能力, 不伪造覆盖.

不预设 2.0 必须在所有成本维度击败空白组, 也不再用理论上的 prompt 缩短宣布性能优化成功. 若某段指导持续增加成本而没有可观察收益, 优先继续删除它. 对表现不清楚的具体功能再做局部消融, 不自动扩展成无限对照项目.

## 9. 入口风格示意

以下是拟议的主入口正文风格, 不是已安装的 SKILL, 也不是固定执行顺序:

> 围绕用户的数学目标开展研究. 自主选择直接证明, 文献检索, 计算实验, 反例搜索或并行协作.
>
> 有项目记录时, 从当前进展和相关指针恢复上下文. 需要已有方法时查询工具库, 再读取选中的卡片, 原文和批注.
>
> 将有复用价值的结果, 方法与失败原因保存在项目中. 以当前进展记录和准确文件指针支持下次续接.
>
> 按研究需要使用 Lean 交互反馈或局部形式化. 验证结果对应实际声明和依赖; 核对关键定义与原目标的含义, 复用未变部分的检查结果.
>
> 按论证需要选择独立复核. 交付结论, 可检查的依据及仍未解决的问题, 说明实际验证范围.
>
> 需要操作时再读取对应说明: 文献与工具库, 保存与恢复, Lean, 规范知识库接收.

2.0 的精简对象是插件对研究过程的额外规定. 数学证明可以很长, 搜索可以广, agent 可以深挖或并行, 由任务和实际判断决定.
